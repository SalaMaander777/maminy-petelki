# Фиксация договорённостей с заказчиком — «Мамины петельки»

Дата фиксации: 2026-10-26. Документ описывает, что согласовано с заказчиком (владелицей), что решено в процессе и что остаётся открытым. Источники: пожелания владелицы, утверждённый дизайн (`docs/design-spec.md`), решения по ходу работы.

## 1. О проекте
Сайт-визитка компании «Мамины петельки» (вязаные изделия ручной работы). Язык интерфейса и текстов — русский. Логотип — `docs/assets/logo.png`.

## 2. Пожелания заказчика (исходные)
- Открывается как у фотографов: логотип, по центру меню.
- Меню: **Каталог, Мастер-классы, Проекты, Отзывы, Акции** (пункт «Мастер-классы» добавлен позже).
- Каталог: карточки товаров — фото, описание, размер, материалы, срок изготовления, цена.
- Внизу сайта: контакты — ссылки на чат в Максе, Telegram, ВКонтакте.
- **Каталог не нужен на главной странице** — он на отдельной странице.

## 3. ОБЯЗАТЕЛЬНОЕ ТРЕБОВАНИЕ: админ-панель
**Заказчику нужна админ-панель, через которую он сам осуществляет полное управление всем контентом на всех страницах сайта.**

Что это означает для проекта:
- Весь изменяемый контент хранится не в коде, а в базе данных и редактируется из админ-панели: тексты и заголовки, фото, каталог (карточки, цены, размеры, материалы, сроки), мастер-классы, проекты, отзывы, акции, контакты и ссылки на мессенджеры, меню, SEO-данные (title/description).
- Заказчик должен уметь без разработчика: добавлять, редактировать, скрывать и удалять записи; загружать и заменять изображения; менять порядок карточек; сохранять изменения так, чтобы они сразу появлялись на сайте.
- Доступ к админке — только по логину и паролю (аутентификация, защита от подбора, секреты в `.env`); интерфейс на русском и понятный нетехническому человеку, удобный и с телефона.
- Это закрепляет роль бэкенда: **backend (FastAPI + SQLModel/SQLite)** отдаёт контент публичному сайту и принимает изменения из админки; контракт описывается в `docs/api-spec.md`.
- Следствие для фронтенда: страницы читают контент из API, а не из статичных файлов. Файл-заглушка с данными каталога (`frontend/data/products.ts`) — временный, будет заменён запросами к API с теми же полями (`name`, `description`, `size`, `materials`, `leadTime`, `price`, `photo`).
- Пустые и скрытые разделы («Проекты», «Отзывы», «Акции», «Мастер-классы») должны корректно отображаться, пока контент не добавлен.

Открытые вопросы по админке (решить до начала разработки):
- Какие именно сущности и поля нужны на каждой странице (список — после согласования содержимого разделов).
- Один администратор или несколько; нужна ли история изменений и черновики.
- Где хранить загруженные фото (диск сервера или внешнее хранилище) и нужны ли автоматическое сжатие и миниатюры.
- Нужна ли возможность менять оформление (цвета, анимации) — по умолчанию нет, только контент.

## 4. Утверждённый дизайн
Подробно — `docs/design-spec.md`; референсы — `docs/design/`.
- **Палитра** из логотипа: бордовый `#7B2346`, розовый `#D98FA8`, кремовый `#F3E6C8`, золотой `#C99A4B`, тёплый фон `#FBF6F0`. Шрифт Nunito.
- **Главная:** логотип, меню на розовой плашке во всю ширину контента (крупный шрифт, края совпадают с фото-полем ниже), большое фото-поле с заголовком и кнопкой «Смотреть каталог», нить, бегущая строка, контакты.
- **Каталог:** отдельная страница, 3 колонки (2 на планшете, 1 на телефоне), карточки с сердечком «сохранить».
- **Анимации:** загрузочный экран с клубком пряжи, появление элементов, нить, пунктирное подчёркивание меню, плавающая карточка и пульсирующая кнопка на фото, заливка кнопок, подъём карточек при наведении. При включённом «уменьшить движение» анимации и загрузочный экран отключаются.
- **Адаптив:** компьютер, планшет, телефон (в том числе iPhone); область нажатия не меньше 44px.
- Заказчику дизайн показывался; **дизайн утверждён.**

## 5. Решения, принятые по ходу
- Логотип обработан: убран фон, получена прозрачная версия; для финала желателен SVG.
- В меню пункты «Проекты», «Отзывы», «Акции», «Мастер-классы» пока ведут на заглушки.
- Реализация фронтенда: Next.js (App Router) + TypeScript + Tailwind; бэкенд — FastAPI; деплой — Docker.

## 6. Что ждём от заказчика
- Содержимое страниц «Мастер-классы», «Проекты», «Отзывы», «Акции».
- Тексты (заголовок и подзаголовок главной, строка бегущей ленты, описание, «О нас» если нужно).
- Реальные фото работ и данные изделий: описание, размер, материалы, срок, цена.
- Ссылки на Макс, Telegram, ВКонтакте.
- Логотип в векторе (SVG), если есть.
- Ответы на открытые вопросы по админ-панели (п. 3).

**Наполнение сайта согласовано отложить на более поздний срок:** до его получения все тексты, цены, фото и ссылки остаются плейсхолдерами.

## 7. План работ
1. Фронтенд по утверждённому дизайну — в работе (`frontend/`).
2. Контракт API и бэкенд: публичное чтение контента + админ-API (`docs/api-spec.md`, `backend/`).
3. Админ-панель: вход, управление разделами и каталогом, загрузка изображений.
4. Подключение фронтенда к API вместо файла-заглушки.
5. Тесты (pytest, Vitest, Playwright), проверка на 375/390/768/1440, доступность.
6. Docker, SEO, релиз; наполнение контентом через админку по мере получения материалов.
