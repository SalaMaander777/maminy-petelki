## 3. Найденные дефекты

### Исправлены (зона backend, минимальные правки + тесты)

**D1. HTTP 500 при огромных числах (серьёзность: средняя).**
- Шаги: войти в админку, затем `POST /api/admin/products` с `{"name":"x","sort_order":1000000000000000000000000000000}`, либо `GET/PUT/DELETE /api/admin/products/99999999999999999999`.
- Ожидалось: 422 или 404 с понятным `detail`.
- Фактически: 500 Internal Server Error (`OverflowError` в SQLite). Затронуты все 5 коллекций, `sort_order` и `{item_id}`.
- Исправление:
  - `backend/app/schemas.py`: типы `SortOrder` (±1e9) и `RowId` (1..2^31-1) для `sort_order` и `ReorderIn.ids`.
  - `backend/app/routers/admin.py`: `Path(ge=1, le=2147483647)` для `item_id`.
- Тесты: `test_garbage_ids_never_500` (25 вариантов), кейсы `sort_order` и reorder в `test_invalid_payload_422` и `test_reorder_unknown_duplicate_and_garbage`.

**D2. Дубликаты пунктов меню принимаются (серьёзность: низкая).**
- Шаги: `PUT /api/admin/settings` с двумя пунктами `catalog` в `menu`.
- Ожидалось: 422.
- Фактически: 200. На сайте два одинаковых пункта, а в `Header` одинаковые `key={href}`, то есть предупреждение React и возможные глюки.
- Исправление: валидатор уникальности slug в `SettingsModel.menu` (`backend/app/schemas.py`).
- Тест: кейс `menu x2` в `test_settings_invalid_422_and_unchanged`.

Контракт `docs/api-spec.md` не менялся. Для D1 и D2 он, по сути, только уточняется: 422 вместо 500 и уникальность slug меню. Стоит добавить в спеку.

Проверено, дефектов нет:
- **Сессии:** подпись и срок действия, cookie `HttpOnly`/`SameSite=Lax`/`Secure` по `COOKIE_SECURE`.
- **Пароль:** bcrypt, выравнивание времени при неверном логине, длина пароля ограничена.
- **Production:** требует `SECRET_KEY` и пароль администратора; `/docs` отключены.
- **Загрузки:** MIME и содержимое проверяются Pillow, имя uuid, перекодирование в WebP без метаданных, отдача только по шаблону `^[0-9a-f]{32}\.webp$`, `nosniff`. Path traversal и SVG/HTML под видом картинки исключены.
- **XSS:** `dangerouslySetInnerHTML` только в JSON-LD, `<` экранируется. Ссылки и фото валидируются на backend (`javascript:`/`data:` отклоняются); в `Footer` и `MasterClassCard` дополнительно `rel="noopener noreferrer"`.
- **Открытые редиректы:** `next` в `/admin/login` проходит whitelist `/admin…`.
- **Утечки скрытых записей:** публичное API фильтрует по `is_published`; истёкшие акции скрыты.
- **Права на файлы:** у загруженных файлов нет битов исполнения и записи для всех.

## 4. Что не покрыто

- Полная сборка и реальный SSR (`next build`/`start`), метаданные в браузере, JSON-LD в реальном HTML — это зона e2e.
- Страницы админки `frontend/app/admin/**` (server/client-связка, drag-n-drop reorder в браузере); покрыты только существующие компоненты (CollectionForm, CollectionList, PhotoPicker, auth, validation).
- Визуальная часть: анимации (Framer Motion, GSAP, Lenis), `prefers-reduced-motion`, адаптив 375/390/768/1440, контраст и доступность — только Playwright и ручная проверка.
- Взаимодействие через Next rewrites (заголовки Host/Origin/X-Forwarded-*, лимит тела при загрузке 8 МБ через прокси) и Caddy — не проверялось.
- Параллельные изменения одной записи (гонки), нагрузка и производительность, миграции схемы БД (используется `create_all`, миграций нет).
- Docker-образы, CI, README (зона devops-seo).

## 5. Итог: GO (условный)

Критичных и блокирующих дефектов нет. Найденные D1 и D2 исправлены и закрыты тестами; все 298 + 125 тестов и линтеры зелёные. Перед выкладкой в production:
1. Убедиться, что при `TRUST_PROXY=true` порт frontend недоступен снаружи (R1).
2. Задать `ALLOWED_ORIGINS`, `COOKIE_SECURE=true`, `SECRET_KEY` и пароль администратора в `.env`.
3. Прогнать e2e по сборке.
