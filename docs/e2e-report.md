# E2E-отчёт — «Мамины петельки»

Дата: 2026-10-26. Проверка на живом стеке: backend FastAPI (порт 8100, временная SQLite + каталог uploads, сид `--demo`) и frontend Next.js (production-сборка копии `frontend/`, порт 3100, `BACKEND_URL` на backend). Код приложения не менялся; всё лежит в `e2e/`.

## Как запустить
```
cd e2e && npm install && npx playwright install chromium webkit
E2E_BASE_URL=http://localhost:3100 E2E_ADMIN_USER=... E2E_ADMIN_PASSWORD=... npx playwright test
```
Тесты админки меняют данные (создают записи с префиксом `E2E…` и удаляют их, настройки и тексты страниц возвращают на место), поэтому запускать только на тестовой БД. `workers = 1`.

Проекты Playwright: `desktop-1440`, `tablet-768`, `mobile-390`, `mobile-375` (chromium), `webkit-desktop-1440`, `webkit-iphone-390` (webkit). Админка гоняется на `desktop-1440`, `mobile-390`, `webkit-desktop-1440`; axe и визуальные снимки — на `desktop-1440` и `mobile-390`; публичные сценарии — на всех шести.

Файлы: `e2e/tests/public.spec.ts`, `admin.spec.ts`, `a11y.spec.ts`, `visual.spec.ts`, `helpers.ts`; конфиг `e2e/playwright.config.ts`.

## Визуальная оценка
Скриншоты: `e2e/screenshots/` (`home-*`, `catalog-*`, `settled-*` — после анимаций, `admin-*`, по каждому проекту). Просмотрены главная и каталог на 390 и 1440, админка (список) на 390 и 1440.
- Главная: логотип, розовая плашка меню на всю ширину контента с краями по фото-полю, большое фото-поле (штриховая заглушка) с белой карточкой заголовка и кнопкой «Смотреть каталог», золотая пунктирная нить, кремовая бегущая строка, бордовый подвал — соответствует `docs/design/home.reference.html` и палитре. На 390 меню переносится на две строки («Отзывы», «Акции» на второй) — читаемо, но менее аккуратно, чем в одну строку (D5).
- Каталог: 3 колонки на 1440, 1 колонка на 390, сердечко, характеристики, цена и кнопка «Заказать», подчёркнутый пункт меню — соответствует референсу. Фото-плейсхолдеры штриховые, так как у демо-изделий нет фото.
- Подвал без кнопок мессенджеров, пока ссылки в настройках пусты (как договорено).
- Админка: на 1440 боковое меню, список с переключателем, ↑↓, «Изменить», «Удалить»; на 390 верхняя панель с кнопкой «Меню», карточки записей — крупные, понятные, русский интерфейс. Стрелки ↑↓ бледные (серые) и мелкие на фоне крупного текста (D6).
- Полностраничный снимок без прокрутки показывает пустую область каталога: карточки появляются при скролле (анимация появления). Это ожидаемо; в `settled-*` снимках всё видно.
- Не проверялось визуально в движении: сама анимация клубка/нити/плавающей карточки (динамика не оценивалась по статическим кадрам; поведение — загрузочный экран исчезает через ~2.5 с — проверено тестом).

## Дефекты
**D1 (средний, frontend, SEO). Название сайта дописывается дважды в `<title>` внутренних страниц.**
Где: `/catalog`, `/sales` и остальные страницы кроме главной. Шаги: открыть `/catalog`, посмотреть `<title>`. Ожидание: значение `seo_title` из админки как есть («Каталог вязаных изделий — Мамины петельки»). Факт: «Каталог вязаных изделий — Мамины петельки — Мамины петельки»; введённый в админке «SEO X» превращается в «SEO X — Мамины петельки». Причина: в `generateMetadata` страниц не используется `title: { absolute: ... }` (на главной используется — там корректно). Тест: `admin.spec.ts` «SEO-заголовок…» (падает на 3 проектах).

**D2 (низкий, frontend, производительность). Загрузочный экран удерживает LCP ≈ 2.9 с.** LCP-элемент — текст «Вяжем уют…» загрузочного экрана; оценка 0.8 при Perf 95. Можно сократить время экрана или не делать его LCP-кандидатом. Не блокирует.

**D3 (низкий, frontend, перформанс). Lighthouse:** неиспользуемый JS ~58 КиБ, устаревший JS ~13 КиБ, неадаптивные изображения (~26 КиБ — проверить на реальных фото), bfcache отключён из-за `Cache-Control: no-store` (сознательно, ради мгновенных правок из админки).

**D4 (информационно). Артефакт контраста при анимации.** Пока карточки/заголовки «проявляются», их цвет ниже контраста (Lighthouse ловит `color-contrast` в этот момент). После анимации контраст в норме (axe — 0 нарушений). Если Lighthouse-оценка для a11y важна для CI, замерять после `data-ready`.

**D5 (низкий, дизайн). На 375–390 меню в две строки** (3+2 пункта). Не ломает вёрстку; при желании уменьшить трекинг/отступы, чтобы поместиться в одну строку или явно сделать 3+2 симметрично.

**D6 (низкий, админка, UX). Кнопки ↑↓ на мобильном слабоконтрастны и тянутся в ряд с «Изменить»/«Удалить»,** на 390 «Удалить» переносится на отдельную строку. Рекомендация: единый размер и более тёмный цвет стрелок. Перетаскивание (drag) на сенсорных экранах не проверялось — работают только стрелки.

**D7 (наблюдение, окружение).** Первый запрос к свежему `next start` вернул 500, а один статический чанк отдал 404, пока сервер прогревался (повторно не воспроизвелось после перезапуска). Также `next start` предупреждает: «does not work with output: standalone» — в Docker запускать `node .next/standalone/server.js`.

Критичных и блокирующих функциональных дефектов не найдено: ошибок консоли и 4xx/5xx-запросов на публичных страницах нет.

## Что не проверено
- Реальный Docker-образ и docker-compose, HTTPS/Secure-cookie (`COOKIE_SECURE=true`), production-режим backend.
- Перетаскивание (drag-and-drop) при перестановке и загрузке файлов; проверена только перестановка стрелками.
- Реальные фото, длинные тексты, большое число записей; галерея проекта с несколькими фото (модальное окно проверено на проекте без галереи).
- Старые Safari/iOS-устройства (только webkit-эмуляция Playwright, 390 и 1440), Firefox.
- Анимации в движении (скролл-эффекты GSAP/Lenis) — визуально по кадрам; MCP-браузер Playwright в этой среде недоступен (нет Google Chrome), снимки сделаны через Playwright Test.
- Lighthouse на десктопном профиле и остальных страницах; замеры под нагрузкой.
- Замена фото в записи и удаление фото из раздела «Фото» (раздел только открывается).
- Одновременная работа нескольких администраторов, истечение сессии (12 ч).
